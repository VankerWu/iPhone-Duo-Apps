# V7 自动发现升级说明

本包基于仓库提交 8923d5b。README、页面、赞赏区域、Issue 表单及所有已收录数据保持原样。

## 检查发现

原有 discover_duo_apps.py 已能从中美免费前 50 榜单和已有 ID 发现线索，但仓库只有 issue-to-catalog.yml，没有定时启动发现脚本的工作流。原脚本会接受否定描述，并在替换候选记录时丢失额外审核字段。

## 本次升级

- 新增独立定时工作流，每六小时运行，也支持 Actions 手动运行。
- 扫描中美免费和付费前 100 榜单；用 iPhone Duo、iPhone-Duo 搜索结果补充榜外候选；对已收录及审核队列 ID 持续查版本说明。
- 搜索和榜单仅用于提供 ID；最终必须通过 Apple Lookup 的 releaseNotes 判定。名称、描述、榜单排名、普通更新均不能单独触发收录。
- 更新说明同一句必须包含 iPhone Duo 和支持、适配、布局等词，并排除已识别的否定或未来计划表达。它仍是启发式筛选，复杂措辞可能漏检或误检，所有新条目一律待确认。
- 候选保留官方图标、商店链接、版本和说明摘录；保留 firstSeen、reviewStatus 及额外审核字段；非 pending 决定不重新自动发布。
- 不更改已有 status、note、sourceLabel、sourceUrl、sourceDate、verifiedDate。元数据刷新使用 --no-charts，避免把无适配线索的热门 App 自动加入目录。
- 与 Issue 收录共享并发锁。推送冲突时重新读取最新主分支并重新执行，不使用强制推送。
- Lookup 全部失败则发现步骤报错，不提交数据；部分来源失败可继续，因此完成一次运行不代表所有来源都成功。

## 安装与数据保护

这是完整源码包，包含当前数据快照；在线仓库后续新增的数据可能比本包更新。**升级现有仓库时，只更新以下四个文件，不要覆盖 docs/data 下的文件：**

1. scripts/discover_duo_apps.py
2. tests/test_discover_duo_apps.py
3. .github/workflows/discover-duo-apps.yml（新增）
4. docs/自动发现升级说明.md（新增）

页面、README、旧工作流和 refresh_metadata.py 无需更换。完成这一次安装后，后续发现和元数据更新由 Actions 自动完成，无需再下载 ZIP 收录 App。

仓库默认分支应为 main；Actions 需要允许 GITHUB_TOKEN 写入内容，分支保护若禁止机器人直接提交则需改为 PR 流程。首次在 Actions 手动运行 “Discover Duo app leads and refresh metadata”，确认日志及数据提交；工作流提交尚未在 GitHub 执行前，不能把本地测试通过视为线上运行成功。

工作流计划为 UTC 00:23、06:23、12:23、18:23（北京时间 08:23、14:23、20:23、次日 02:23），GitHub 可能延迟，长期无活动的公开仓库也可能被暂停计划任务。

若 Pages 使用 docs 目录的分支发布，沿用现有发布设置；若改成仅由 push 触发的自定义 Actions 部署，请另行验证机器人提交能否触发部署。

## 覆盖范围

这是定期扫描候选池，不是全 App Store 更新订阅。公开搜索不会穷举所有 App，也不保证索引更新说明；不在这些来源中的 App 仍可能漏掉。Lookup 通常提供当前版本说明，短期内连续发布也可能错过旧版证据。保留原 Issue 提交流程补充漏项；本升级不承诺发现全部新适配 App。

本地验证：python -m unittest discover -s tests -v。
